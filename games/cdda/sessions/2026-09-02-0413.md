# Cataclysm: Dark Days Ahead 플레이 세션 - 2026-09-02 04:13 UTC

## 목표

- 저장소에 새로 만든 `qa/runner/play_cdda.py` 드라이버로 CDDA 커브시 빌드를
  실제로 구동해, 캐릭터 생성부터 게임 진행까지 조작법을 스스로 익히며 전
  과정을 로그로 남긴다.

## 행동 로그

1. [관찰] 메인 메뉴, "New Game" 서브메뉴가 팝업으로 열려 있고 커서가
   "Preset Character"에 있음.
   → [가설] 방향키(↓)로 커서를 "Play Now! (Default Scenario)"로 옮길 수
   있을 것이다.
   → [행동] `down` 키(ESC[B) 2회 전송.
   → [결과] 커서 위치 변화 없음 (팁 텍스트만 자동으로 바뀜 → 화면 자체는
   갱신되고 있었음). 가설 기각.

2. [관찰] 위 실패 이후에도 커서가 그대로임.
   → [가설] ncurses가 애플리케이션 키패드 모드(smkx)를 켰다면 일반 방향키
   시퀀스 대신 vi 스타일 키(`hjkl`)를 받을 수 있다.
   → [행동] `j` 키 2회 전송.
   → [결과] 커서가 "Preset Character" → "Play Now! (Default Scenario)"로
   두 칸 이동. 가설 확인됨 → notes.md에 기록.

3. [관찰] 커서가 "Play Now! (Default Scenario)"에 위치.
   → [행동] `enter` 전송.
   → [결과] "Loading files Dark Days Ahead" 로딩 화면으로 전환.

4. [관찰] 로딩 화면이 "Finalizing Crafting recipes" → "Verifying Skills"로
   단계가 넘어감.
   → [행동] 약 30초간 대기(빈 명령 전송으로 스냅샷만 갱신).
   → [결과] 로딩 완료, 실제 게임 화면(사이드바 + 맵)으로 진입. 캐릭터명
   "Andreas Jacob", 시작 위치 "evac shelter A-23", 목요일 5월 20일
   오전 8:00, Str 9 / Dex 6 / Int 5 / Per 7.

## 이번 세션에서 새로 알아낸 것

- 메뉴 탐색은 방향키가 아니라 `hjkl`로 한다 (notes.md에 반영).
- "Play Now! (Default Scenario)"는 캐릭터 생성 화면을 완전히 건너뛰고
  무작위 특성/직업으로 바로 게임을 시작시킨다.
- 첫 실행 시 world 데이터 초기화(로딩)에 20~30초가량 걸린다.

5. [관찰] 캐릭터 "Andreas Jacob" 생성 직후 `l`(동쪽 이동) 전송.
   → [행동] `l` 1회.
   → [결과] 플레이어가 한 칸 동쪽으로 이동, `Move` 카운터 0→102,
   `Activity: None`→`Moderate`로 변화. 메뉴뿐 아니라 실제 이동도 `hjkl`로
   동작함을 확인.

6. [관찰] `i`(인벤토리)를 보내려 했으나, 명령 전송 도중 샌드박스 컨테이너가
   사용량 한도로 재시작되어 세션 드라이버·게임 프로세스가 모두 죽고 요청이
   무기한 블록됨.
   → [행동] 프로세스 정리 후 세션 드라이버 재기동.
   → [결과] 새 게임 프로세스는 항상 메인 메뉴에서 시작한다는 것과, 이전
   캐릭터("Andreas Jacob")는 저장된 적이 없어 "Load" 메뉴에서
   "Rolinda has no characters to load!"로 사라진 것을 확인 — **명시적으로
   저장하지 않으면 진행 상황이 남지 않는다**는 중요한 사실을 알아냄.
   디스크에 쓴 파일(빌드 결과물, 이 로그들)은 컨테이너 재시작에서도
   살아남는다는 것도 함께 확인.

7. [관찰] 메인 메뉴에서 `esc`를 눌렀더니 "Really quit? (Case Sensitive)
   [Y]es [N]o" 확인창이 떴다.
   → [가설] `esc`는 메인 메뉴에서는 "뒤로가기"가 아니라 "종료 확인"으로
   동작할 것이다.
   → [행동] `N`으로 취소.
   → [결과] 가설 확인, notes.md에 반영. 메인 메뉴가 아닌 다른 화면에서는
   `esc`가 정상적으로 "취소하고 이전 화면" 역할을 했다(인벤토리 등).

8. [관찰] `New Game` → `hjkl`로 "Play Now! (Default Scenario)" 재선택 →
   두 번째 캐릭터 "Hope Abrams" (Str 10 / Dex 6 / Int 9 / Per 7) 생성,
   같은 "evac shelter A-23"에서 시작. 시작 장비: 반바지/브라/하이킹
   백팩/하이킹 부츠/청바지(주머니에 아이템 3개)/니트 스카프/양말/티셔츠/
   손목시계/스마트폰(도구)/사진술 관련 교본 "Through the Lens"/현금이 든
   지갑.
   → [행동] `i`로 인벤토리 확인 → `esc`로 닫기 → `j|j|l`, `j|j`, `j` 순서로
   대피소 내부를 이동해 남쪽 문 쪽으로 진행.
   → [결과] 닫힌 문(`+`)으로 이동하니 자동으로 열려(`'`)로 바뀌고 시야가
   확장됨(Lighting: very dark → bright). 이동 1회당 게임 내 시간이 1초씩
   흐름을 확인(`Time` 필드).

9. [관찰] 문을 연 이후 화면에서 실제 플레이어 위치(`@`)와는 별개로 이전
   문 근처 자리에도 `@`처럼 보이는 표시가 함께 나타남.
   → [가설] 렌더링 캡처(pyte) 쪽 잔상이거나, 실제로 다른 개체가 그 자리에
   있는 것.
   → [행동] `Q`(shift+q, 흔한 종료 단축키 추정)를 보내 반응을 관찰.
   → [결과] 화면에 아무 변화 없음(종료 확인창도 뜨지 않음) → 이 키에는
   기본 바인딩이 없는 것으로 보임. 원인은 다음 세션 숙제로 notes.md에
   기록하고, 안전하게 세션 드라이버를 종료함(저장은 하지 못한 채 종료 —
   이번 세션은 순수 탐색 목적이라 진행 손실은 허용 가능하다고 판단).
